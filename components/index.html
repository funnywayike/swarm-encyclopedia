组件百科
算法不是 45 段独立代码，是模板 + 积木

这一页回答一个问题：「45 个算法背后的代码是怎么组织的」。先给结论：真正手写的只有算法主循环模板和 13 个通用组件——交换、插入、OX 交叉、双桥扰动、2-opt 下探……所有算法从同一张组件注册表里取件。新增一个算法的平均成本，从第一版的「一整天」降到组件化后的「一小时」。

一、两层组件化架构

层级组件是什么单一事实来源谁在用
第一层：TSP 通用组件13 个跨算法复用的函数（下表），覆盖构造→扰动→交叉→编码全流程py/components.py + COMPONENTS 注册表45 个 TSP 算法（py/solvers.py）
第二层：问题域引擎组件域引擎骨架件：最优追踪 bump/argbest、二进制算子（均匀交叉/逐位变异/翻转）、贪心替换、排列域算子（OX/交换/插入/打磨）py/domain_components.py（S1-1 组件化）背包/连续/多目标/图着色/装箱 5 域全部算法（py/domains.py）
第三层：排列域算法库_pm_* 系列通用排列算法（HC/SA/TS/GA/ABC/WOA 的排列版），域差异全部压进 ctx 解码器py/domains.py（内核收编自第二层组件装配）图着色 + 装箱两个域的 7 算法——同一份代码

设计原则照搬 jMetal：算法 = 主循环模板 + 组件目录。组件只依赖「排列 + 距离/代价」这个最小接口，不关心具体问题——所以 2-opt 下探既服务 TSP 也服务 GRASP 的打磨步，OX 交叉在 GA/DE/TLBO/SFLA/SOS 五个家族里语义完全一致。

组合配方引擎把算法拆成七个固定槽位：初始化 → 选择 → 交叉 → 变异 → 替换 → 局部搜索 → 终止。 每个槽位从下表挑一个组件，一份「配方」就是一张装配清单—— Memetic 配方页有完整示范。 本节组件全部是纯组件（composable: false）：不能自己跑，必须有宿主配方或算法。

三、复用冠军与调用链故事

组件为什么被反复复用
2-opt 下探排列域最强的通用局部搜索。它同时扮演三个角色：独立算法（2-opt/ILS/VNS 的本体）、播种抛光（几乎所有种群算法的 memetic 周期）、重置下探（SFLA 反射步 / SSA 警戒远跳的预算制下探）。一个函数三种用法。
OX 顺序交叉「从供体学习」在排列域的诚实翻译。连续域算法离散化时，凡是带「向好解移动/吸收特征」语义的（DE/TLBO/SFLA/SOS/GA），逐位抄会产生重复城市——OX 是文献标准解法，也是「是否真在优化」自动测试的重点照顾对象。
双桥扰动切 4 刀换段重排，产生的解不可被 2-opt 还原——这是 ILS「跳出局部最优」和 SFLA「重置蛙」能真正逃逸的数学保证。随机 2-opt 逆转太轻，双桥才够深。
随机键编码排列↔连续向量的双向映射。PSO/GSA/CEM 这些「原生连续」算法靠它在排列域工作：粒子位置是实数向量，解码时排序成排列。代价是解码有噪声（两个相近向量可能排出不同排列），这是这些算法离散化后变弱的主因之一。

四、排列域「问题适配」范式：一份代码服务两个域

图着色和装箱的 7 个算法（HC/SA/TS/GA/ABC/WOA + random 基线）只写了一份代码。秘密是 ctx 接口——域差异被压进五个方法：

ctx 方法图着色域装箱域TSP 对照
random(rng)随机顶点排列随机物品排列随机城市排列
decode(perm)FF 染色 → (色数, Σci²)FF 装箱 → (箱数, Σ剩余²)路径长度
diff(a, b)字典序增量（供 SA 的 Metropolis 判据）标量差
solution(perm)颜色数组（画染色图）物品→箱分配（画柱状图）路径序列
polish(perm)_pm_polish 预算下探（供 SA 重启后使用）2-opt 下探

效果：给这两个域新增算法 = 抄一行模板；给排列域新增问题 = 只写一个 ctx（约 60 行）。「算法 = 机制，问题绑定 = 编码+解码」在这里从口号变成了代码结构。

五、组件化的收益与代价

做法好处主要风险
每个算法各写一套邻域 / 扰动单个算法自成一体，读代码不用跳转代码漂移：同一个「交换」在不同文件里会出现细微不同的实现，对比实验的差别可能来自实现而不是算法
算法主循环 + 从注册表取通用组件新增算法只写主循环；同一个组件被所有算法共用，修一处全部受益，组件有独立测试组件里的 bug 会传染所有调用方
排列域 ctx（问题只写解码 / 邻域 / 评估）新增一个排列问题只写一个 ctx，现有算法直接可用各域的平台（plateau）特性差异大（见各域页的常见问题），算法默认参数必须按域实测标定
