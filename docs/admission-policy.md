# 收录与取舍规范（Admission & Trade-off Policy）v2

> 版本：v2（2026-10）｜ 状态：**生效**
> v1（2026-09-26）定了「五闸门」；v2 在此基础上补了：**保真度**、**成本核算**、**取舍规则**、**退役流程**、**可公开核实的文献硬性规定**，
> 并更新了已过时的「冻结条款」。配套：候选池 `data/discovery.json`、计划 `docs/PLAN-v0.1.md`。

## 0. 目的与范围

1. **存量可解释**：每个已收录的算法/问题，都能说清它为什么在这里、可信到什么程度。
2. **增量有规矩**：新增按闸门打分，结论由分数与规则决定，不靠临场判断。
3. **取舍有依据**：资源有限（维护成本是乘法增长的），什么不收、什么降级、什么退役，有成文规则。

**本站是什么**：让人在浏览器里或命令行里，用自己的标准化数据跑群智能/元启发式算法，并读懂这个领域的算法与问题。
**本站不是什么**：不是求解器库（不追求与专用求解器比性能）；不是综述论文；不做服务端；不收没有可核实出处的内容。

## 1. 纳入漏斗

```
全量发现池（算法 ~600+ 提出 / 问题 ~60–80 教科书级 + 各应用基准）
  ↓ 闸门 A · 一票否决
候选池（data/discovery.json，逐条评分）
  ↓ 闸门 B–E · 量化评分 → 三轨分流
收录册独立页 / 配方·词条轨 / 批评词条（F9）
  ↓ 问题侧再过：闸门 F · 保真度声明
```

## 2. 算法纳入 · 五闸门（沿用 v1）

| 编号 | 闸门 | 量化判据 | 不过 → 去向 |
|---|---|---|---|
| A | 溯源性（一票否决） | 原始论文**可在公开文献中核实**（见 §6）。无法核实直接出局 | 拒绝 |
| B | 机制独立性 | 状态转移/算子结构**不能**由站内七槽组件等价装配。能等价装配 = 机制不独立 | 换皮 → F9 批评词条 |
| C | 文献证据 | ≥1 经典出处；加分：第三方独立复现 / 标准基准有成绩 / 顶刊顶会 | 证据弱 → 词条轨 |
| D | 影响力分档 | 经典 >1000 引；成熟 200–1000；新范式（2020s）≥50 引且 ≥3 年独立跟进 | 不达 → 词条轨观察 |
| E | 可执行性 | 能落站内引擎（编码明确 + Pyodide 可跑）→ 实测级；否则文献级 | 仅文献级 |

**三轨判定**：A–D 全过 + E 实测级 → 收录册独立页；B 判「可装配」→ 配方；证据/影响力不足或仅文献级 → 词条；A 过、B 不过 → F9 批评词条（必须挂批评视角）。

### 2.1 成本核算（v2 新增）

「算法 × 问题域」是**乘法**：45 个 TSP 算法 × 十几个域，每一格都要有黄金快照、冒烟与「胜随机」检验。因此：

- 新算法**至少交付**：TSP 内核 + 一个其他编码的适配（位向量/排列/实向量/指派之一），并进黄金快照；
- 其余域的适配按需，**每格必须过「胜随机」门**，没过的撤下并留痕，不得「半挂」；
- 登记「覆盖了哪些编码」「每域验证状态」，缺口显式列出，而不是默认没有；
- 新算法必须过「是否真在优化」自查三问（关掉局部搜索仍比初始解好；1 代→200 代有真实进步；收敛后扰动能踢出新结构）。

## 3. 问题纳入 · 闸门

| 编号 | 闸门 | 量化判据 | 不过 → 去向 |
|---|---|---|---|
| A | 可实例化（一票否决） | 能写成 (解空间, 目标函数, 约束) 三元组 | 纯概念不收 |
| B | 形态归属 | 归入某个问题类（`data/problem_groups.json`）；装不下 = 申请新类评审 | 无归属 → 类评审 |
| C | 文献/工业地位 | NP-hard 或教科书经典，或应用地图有真实行业条目背书 | 弱 → 词条轨 |
| D | 可映射性 | **至少接上 1 个收录册算法**（实测或文献级） | 零映射 → 不建页 |
| E | 变体判据 | 与母问题差异可量化（约束类型/目标数/解空间变化） | 差异不足 = 非新变体 |
| **F** | **保真度声明（v2 新增）** | 必须声明 `standard / simplified / illustrative`，非标准必须写一句「与标准定义的差异」（见 §4） | 不声明 = 不得建页 |

问题侧三轨：独立问题页（A–D、F 全过）／词条（`entry`）／拒绝。

### 3.1 问题挖掘的优先级（v2 新增）

候选问题打分 = **标准程度 × 可上传性 × 复用现有内核的程度 ÷ 建模成本**，各项 0–3 分：

- 标准程度：有公认定义与公认基准实例（TSPLIB、OR-Library、DIMACS、CSPLIB、QAPLIB、BBOB、CEC、ZDT/DTLZ…）得高分；
- 可上传性：有公认的数据文件格式、用户能拿自己的数据来用得高分；
- 复用度：能直接用已有编码族与内核（位向量/排列/实向量/指派）得高分；
- 建模成本：需要新编码族、新解码器、新数据结构的得低分。

**收敛条件**：每个编码族饱和到「该族主要公认基准都覆盖」就停，不追求穷尽。
挖掘来源：公认基准库 → 综述 → 应用地图里反复出现的形态。

## 4. 保真度三档（v2 新增）

| 档 | 定义 | 页面徽标 | 上传时 |
|---|---|---|---|
| `standard` 标准模型 | 与教科书/文献定义一致，结果可与文献对照 | ✅ | 无提示 |
| `simplified` 教学简化模型 | 问题本身是真的，但解码/约束做了教学级简化，**数值不能与文献对照** | ⚠️ + 差异说明 | 校验器给警告 |
| `illustrative` 示意模型 | 只借这个问题的名字演示形态，**模型并不是该问题本身**（含「P 类对照」） | 🔶 + 差异说明 | 校验器给警告 |

- 登记位置：`py/entryseq.py` 里 `@_objective(..., fidelity=..., note=...)`（**必填**，缺了导入即报错）；其余域的目标函数按标准定义，由 `registry.fidelity()` 统一返回。
- **示意模型不得进入「标准基准」类列表**；升级路径：补足模型 → 改档 → 黄金快照里记录变化原因。
- 现状（2026-10）：词条域 57 个变体中 **9 标准 · 27 简化 · 21 示意**；其余域均为标准模型。

## 5. 取舍规则（v2 新增）

| # | 取舍 | 规则 |
|---|---|---|
| T1 | 广度 vs 保真度 | 任何问题不得叫「可跑演示」而不带保真度徽标；宁要少量标准问题，不要大量示意问题；示意可留，但必须标注 |
| T2 | 算法数量 | 收录无上限，分三层：独立页（机制独立+可实测）／配方（可由七槽装配）／批评词条（换皮，只挂批评）。能由现有组件等价装配的，不建独立页 |
| T3 | 维护成本 | 见 §2.1：新算法至少 TSP + 一个其他编码；其余域按需、每格过门 |
| T4 | 问题优先级 | 见 §3.1 打分；公认数据格式优先 |
| T5 | 语言 | v0.1：英文 README 首屏 + 站点中文；完整英文站不在 v0.1 |
| T6 | 服务端 | 不做；「在线上传」= 浏览器本地运行，数据不出本机 |
| T7 | 撤下的东西 | 要么重做，要么在 CHANGELOG 里写明「已移除，原因」；**不留「半撤下」状态**（列表里有、点了崩） |
| T8 | 运行时分发 | Pyodide 随仓库分发（离线可用、国内稳定） |
| T9 | 测试成本 | 快慢分档：快档每次提交，慢档（黄金快照 + 冒烟矩阵）合并前/每晚 |

## 6. 文献真实性硬性规定（不可协商；v2 改为「可公开核实」）

1. 每个正式引用必须能被**公开核实**：优先带 DOI；期刊条目要能被 `tools/check_citations.py`（Crossref）核对通过——**作者、年份、刊名、卷、页（或文章号）都要对**。
2. 工具核对不了的（书、学位论文、会议论文、中文文献）要**人工核实并登记**到 `data/citation_overrides.json`（写明理由与可访问的链接）。
3. 不确定 = 引用字段留空并标「待核」。**禁止编造或凭印象补全作者/年份/刊名/卷页。**
4. 批评词条的批评锚点统一指向 Sörensen 2015（*Metaheuristics — the metaphor exposed*, ITOR 22(1):3–18）。
5. 调研报告等内部资料**不得作为出处**，也不得在公开页面里被引用（页面上不出现「综述 §…」「报告 §…」）。
6. 发版前抽查：`python tools/check_citations.py --sample 10`，结果记入 CHANGELOG；全量核对结果见 `docs/citation-report.md`。

> 教训（2026-10 清扫）：45 条算法引用里有 8 条卷/页/刊名有误、2 条作者名单有误；问题轴数百条引用从未核对。
> 「靠记忆写出处」不可靠，所以改为「工具核对 + 人工登记」。

## 7. 退役与降级流程（v2 新增）

发现某算法/问题**无效、失真或出处有误**时：

1. 标记 `deprecated`（页面保留，顶部横幅说明原因与替代品；旧地址保持可访问）；
2. 一个版本后移除或降级为词条；移除时在 `data/moved_pages.json` / CHANGELOG 登记，并留重定向；
3. 黄金快照里相应条目一并移除，**提交说明写清原因**（有意变化必须解释）。

## 8. 冻结条款（v2 更新）

v1 的「VRP / 车间调度 / 动态优化只允许词条形式」**已作废**：这些问题现在都有页面与教学级模型，冻结条款与事实不符。
v2 改为：**按保真度分档管理**——简化/示意可以有页面，但必须带徽标；升级为标准模型是第一梯队任务（见 `docs/problem-audit.md`）。

## 9. 候选池 schema（`data/discovery.json`）

```jsonc
{
  "type": "algo | problem",
  "name": "...", "en": "...",
  "family": "F2",                     // 算法候选的家族
  "evidence": "...",
  "gates": {"A": "pass", "B": "fail", "C": "pass", "D": "pass", "E": "fail"},   // 问题多一个 "F"
  "gate_notes": {"B": "..."},
  "verdict": "收录册页 | 配方 | 词条 | 批评词条 | 拒绝",
  "status": "proposed | admitted | rejected",
  "fidelity_target": "standard",      // 问题候选：打算做到哪一档
  "src": "必须可核实（DOI 或登记在 citation_overrides.json）",
  "note": ""
}
```

## 10. 执行流程

1. 挖掘 → 写入 `discovery.json`（`status=proposed`，逐条 gates + evidence + 出处核对）；
2. 按 verdict 三轨纳入；独立页走建页流程（脚手架见 `docs/CONTRIBUTING.md`，阶段 4 提供）；
3. 每纳入一条同步补 ≥1 条 mapping（问题侧 D 闸门联动）；
4. 验收链：`python build_pages.py && python selfcheck.py` + `pytest tests/`（含黄金快照与冒烟矩阵），基线只增不减；
5. 引用核对：`python tools/check_citations.py`；
6. 提交一阶段一提交；有意改变行为（黄金快照变化）必须在提交说明里写清原因。
