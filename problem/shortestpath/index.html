最短路径 Shortest Path Problem（SP）

抽象问题类型 · Ⅺ 图与网络流类（含多项式可解的对照问题）

In brief

The Shortest Path problem finds a minimum-weight path between two nodes and is solved in polynomial time (Dijkstra). It is included as a contrast: the site searches a real vector of node priorities, decodes a path by always moving to the highest-priority unvisited neighbour, and compares with Dijkstra's optimum. The encoding is highly redundant and fine only for small graphs.

抽象定义

模型：带权图 G=(V,E,w) 中从起点 s 到终点 t 的最短路径：

min Σ_{e∈P} w(e)  s.t.  P 是 s→t 的路径

路径规划、导航、网络路由、依赖关系图的关键路径、动态规划的图形式……几乎所有「找一条最省的路」的问题。最优子结构是它能被高效求解的原因：最短路的任何一段仍是最短路。在网络里，每一次查询毫秒级即可完成，所以它是地图导航、路由协议（OSPF 即 Dijkstra）的基石。

与同族问题的结构差异

与最长路径形成鲜明对比：把「最短」改成「最长」就丢了最优子结构，从 O(E log V) 跳到 NP-困难。本页作为 P 类对照，让读者看到「有结构的问题」与「没结构的问题」在同一张图上的差异。

  • 边权为负：Dijkstra 不再适用，Bellman–Ford O(VE) 可检测负环；Johnson 算法做全点对。
  • 加约束就难：资源受限最短路、带时间窗最短路、k 条互不相交路径等是 NP-困难或更复杂；这些正是车辆路径问题的子问题（列生成里的定价问题）。

求解路径

  • 精确（多项式）：Dijkstra (1959) O((V+E) log V)；A* (Hart、Nilsson 与 Raphael 1968) 用启发函数加速；Bellman–Ford；Floyd–Warshall（全点对）。路网上还有 contraction hierarchies 等预处理加速，使连续路网毫秒级查询。
  • 元启发式（对照）：遗传算法里的优先级编码 (Gen & Cheng 2000)——每个点一个实数优先级，从起点出发每步走向优先级最高的未访问邻居，保证解码出的一定是简单路径——就是本页的做法。

计算复杂度与可近似性

多项式可解：非负权 Dijkstra O(E + V log V)（斐波那契堆）；有向无环图线性时间；整数权有更快的算法（Thorup 1999 在 O(E) 内解无向整数权图）。这是组合优化里最彻底「解决了」的问题之一。不过，一旦图上有负环、或要求路径满足资源约束（时间窗、油量），问题就变成 NP-困难——这是它与车辆路径问题的接口。

基准实例与已知结果

最短路的标准基准是 DIMACS 第 9 届实现挑战赛（美国路网，从纽约到整个美国的 2300 万个点），以及随机 / 网格 / 小世界图；评价指标是查询时间与预处理时间，因为解都相同。元启发式研究常用小规模随机图验证编码，没有统一基准。

本站的建模方式

词条域里的实数向量变体（保真度：标准模型）：n=8–24 个点的随机连通加权图（权重 1–15）；起点 0，终点取离起点跳数最多的点（保证起终点不直接相连）。解 = 每个点的「优先级」（实数向量）；解码从起点出发，每步走向优先级最高的未访问邻居；走进死胡同则按 4000 计（重罚）。目标 = 路径总权。实例里附带 Dijkstra 的最优值作对照。

与文献标准的差别：搜索的是点的优先级而不是路径本身，所以同一条路径有大量等价的优先级向量（高度冗余的编码）；规模小（≤ 24 点）时随机优先级碰巧找到最优的概率也不低——这正是 P 类问题的特点。
